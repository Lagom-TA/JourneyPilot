# ADR-0010：自然语言需求与研究方案直传各角色

状态：已采纳
影响：`planning/requirements/`、`planning/graph.py`、`planning/research/`、`planning/delivery/`

## 决定

深度规划只把少量基础信息、用户原话、追问回答和后续补充保存为结构化身份与当前需求文字。
模型据此写出简短的研究与安排方案，并为目的地、交通、住宿和行程组合分别写下任务；用户
确认这一版方案后，各角色直接接收相关基础信息、需求文字和自己的任务，自行决定查询和工具参数。

计划门修改与运行中 supplement 统一转成 `IntentAmendment`，追加到同一条当前需求并产生新的
`PlanningGeneration`。Research Packet、Catalog、Workspace 与 Delivery Manifest 绑定同一 generation。
运行取消、租约、预算、期限和工具结果记录继续保留。

需求理解发生在 Run 内：`understanding_agent` 以强模型角色带真实工具协议工作，可按需联网与
查询真实地点，先查后问；`understanding_gate` 暂停等待回答，回答进入同一份需求文字。基础身份
由理解产出（地点来自工具查到的真实记录），入口不要求身份预先齐全。

## 为什么

用户表达不需要被拆成逐条意图、约束、来源裁决和精确查询清单。把这些中间产物作为唯一权威，
会让每个调用点重复解释同一句话，也让模型无法根据真实资料调整研究。当前需求文字与模型任务
说明保留原意，各角色在自身工具范围内工作，更接近真实的旅行研究和安排。

## 替代方案与为什么没选

- **按 clause 归一化为唯一 Request Contract**：需要维护整套语义分类、冲突裁决和确定性查询计划，限制实际研究。
- **只把原文传给 Worker、不建立当前方案**：用户无法在正式研究前确认研究和安排设想，修改也没有稳定版本。
- **在当前需求文字之外并行保留一份结构化合同**：会出现两套需求权威，合同里的查询和操作清单继续约束执行。

## 后果

- 服务端不归一化用户表达；持久化数据只按当前结构读写，数据库按当前迁移创建。
- 研究方案、任务说明与当前需求文字随 `PlanningGeneration` 失效；只引用当前 generation 的方案和研究结果。

## 对应不变量

INV-INTENT-004、INV-PLAN-001。
