## 1 用户反馈

> 我现在发现了一个问题，就是我们在拓展多个目的地的时候，它会导致于我们的整个的高度有所变化，但我不希望这种情况出现，我希望我们的这一块的高度和大小是保持稳定的，并且我们的案件也是保持稳定的。所以说我有一个方法，就是说它在选择多个目的地的时候，我们的开始日期和旅行偏好可以整体地向下平滑地移动一段距离，把这个位置空出来。并且呢，我们也要优化在开启拓展多目的地之前，我们的行间距，让它尽可能充分地利用我们的高度。

截图：`output/polish/20261031-1130-home-destination-stability/feedback-1.png` 为首页按条件规划、已有北京并展开新增搜索框；`feedback-2.png` 为相同区域收起新增搜索。用户希望卡片与“开始规划”按钮稳定，而不是收起时把空余高度都堆在偏好和按钮之间。

## 2 现象与发生条件

首页“新旅行”的按条件规划，已有至少一个已确认目的地，点击“新增目的地”展开搜索或点击“关闭新增”收起。用户截图为局部画面，无法确定实际 CSS 视口；实测覆盖 2000×880、1440×900、390×844。以同一视口、相同已选地点及其他表单内容，只切换新增状态作为稳定性比较；另检查多地点换行、更多偏好和移动端。

## 3 根因

- `frontend/src/features/travel/components/planning/DestinationTokenField.tsx:550–555、623–650` 内部管理新增状态；已有地点且展开时，搜索框作为 token 首行之后的普通布局内容条件渲染。`frontend/src/index.css:1269–1283、1365–1384` 为搜索框和间距分配额外高度，候选列表则是独立浮层，不是这次撑高的原因。
- `frontend/src/features/travel/components/planning/TripPlanner.tsx:465–532` 依次排列路线、日期/同行/预算和旅行偏好；`frontend/src/index.css:1522–1528、1564–1568` 使用固定间距，新增行会先把下方内容推下。两个模式面板叠放在同一个 grid 中，隐藏面板仍参与高度计算（`TripPlanner.tsx:356–435`、`index.css:653–672`）；当条件面板内容超过当前共用空间时，面板及其后的共享按钮和卡片一起增高。实际增量还受地点换行和视口影响。
- 主按钮在两个面板外的共享操作区（`TripPlanner.tsx:535–548`），不是按钮自身引起变化。当前普通首页没有为新增搜索时日期和偏好的位置变化提供平滑过渡。责任方止于首页表单与布局，不涉及服务端。

## 4 方案

目标状态：在相同内容和视口下，展开或收起新增目的地时，规划卡外框及底部“开始规划”的位置和尺寸不变；日期/同行/预算与旅行偏好平滑下移或复位，给新增输入行让位。收起时合理分配行间空间，让表单充分利用既有高度，不把预留空间集中成底部大空白。

必须做：

- 在已有 1–4 个地点时，仅展开或收起新增输入，不因搜索行出现而改变卡片或共享主按钮几何；覆盖地点已换行的情况。日期/同行/预算与旅行偏好作为整体平滑下移/复位，不遮挡其他控件；开关仍在目的地首行。稳定性包含过渡过程中，不能先跳动再复位。
- 收起状态均匀、自然地利用可用垂直空间，不人为留一整块空白行，不为了稳定而无必要地加高卡片、缩小交互目标或裁剪内容。两种规划模式切换继续共享稳定卡片和主按钮，并保留各自草稿。
- 兼容不同内容与视口：不使用会截断地点、偏好或错误信息的固定高度；当新增已确认地点造成额外换行、展开更多偏好、显示错误或内容确实超出可用空间时允许随内容合理增高，但同一内容仅切换新增开关时仍应保持稳定。小屏允许自然换行和纵向滚动，不横向溢出。
- 保持零站基础搜索、五站上限、地点确认/删除/排序、搜索焦点与候选交互；不改变已确认地点、草稿和提交语义。保留日期、同行、预算、偏好操作及无障碍名称；遵循 `prefers-reduced-motion`，减少动态效果时直接到达目标布局且仍保持几何稳定。
- 目的地控件也用于卡内需求确认；若修改共用组件或样式，确认该入口不被首页专用布局假设破坏。

执行者自己决定：在现有组件或样式中如何分配空余空间、驱动过渡及选择响应式策略；动画的具体时长和缓动以自然、可感知且不拖慢操作为准。优先复用现有首页测试夹具和几何辅助函数。

不许碰：后端、API/SSE/持久化、地点身份及五站规则、日期/预算/旅行规划业务规则、右侧素材和无关页面；不调用真实付费模型或写真实用户数据。`frontend/src/index.css` 已有与本任务无关的工作区改动，须保留；不覆盖其他任务或其证据，不提交、不推送、不 stash、不切分支。
