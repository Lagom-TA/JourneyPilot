## 2 额外核查的旅行产品

- [Wanderlog](https://wanderlog.com/) 官方首页正文明确写出 “Your itinerary and your map in one view”。这能支持“日程与地图共处”的信息架构，但不是对它登录后编辑器的交互实测。
- [PamPam](https://www.pampam.city/) 官方首页正文取得 “Interactive Map / Map animation / Printable map” 与 travel maps / guides / itineraries 介绍。可作为地图表达旅行内容的参考，尚未操作其编辑器。
- [60fps 的 Airbnb sheet 条目](https://60fps.design/shots/airbnb-add-guests-in-sheet-interaction) 搜索摘要可以确认主动点击按钮改变内容的描述，未观看录屏。动画风格不直接移植到本项目。

这批公开内容能支持信息架构与交互决策。完整视觉仍需以本地稿和执行后的真实工作台截图判断；不拿落地页的营销画面代替日程可读性。

## 3 本轮确定的视觉方向

目标是让用户读到一趟旅行。现状中五天被包成五个同样的圆角按钮，日标题又被包进一张卡片，交通内外两层标题争抢同一层级。增加装饰会放大这个问题。

### 3.1 面板宽度与地图

- 大桌面把当前 420/440px 面板加宽到约 600–640px；1440px 视口约 560px，1280px 约 520px，具体断点由执行者结合实屏确定。
- 地图控件、详情浮层、相机可视区域随面板的实际宽度调整；不能只改 CSS 宽度、留下 `464/484` 或相机 `440/460` 这类旧常量。
- 左侧维持一块连续纸面，旅行标题与操作在上，日程内容在下独立滚动；继续沿用现有地图工作台，不创建新结果路由。

### 3.2 全程概览

- 五张独立边框卡改为按天的连续目录。左侧轻量日序，右侧日期／城市、自然标题、必要的地点线索，用留白与细分隔线建立节奏。
- 标题居主位，日期城市居次位。彩色“第 N 天”胶囊不在每一行重复抢眼。
- 允许单行或两行标题，不能截成读不通的碎句。5 天与最多 14 天都要有清晰的滚动与当前项。
- 点击整行进入某天，键盘 Enter/Space 同样有效；悬浮不打开、不改日期、不滚动、不移动地图。

### 3.3 日详情

- “第 N 天 · 日期 · 周几 · 地点”与天气同排，天气靠右。自然标题在下一行。
- 日标题区域不再使用独立圆角卡、描边或灰底。可以用页边距、字号、字重和章节分隔建立层级。
- 地点活动沿时间顺序阅读，弱化通用表单式外框；交通作为衔接块。不是要求把所有有明确语义的容器全部移除。
- 窄屏确实装不下时可让天气自然换行，不能遮住日期或用极小字号勉强塞入。桌面主验收尺寸必须同排。

### 3.4 交通

- 城际交通用简洁票据结构：一行“图标 + 高铁 G382 + 时间范围”，中间清楚站名，底部左时长、右费用。
- 去掉冗余“交通／班次／直达／时长／费用”等标签及铁路代码；飞机实际有助识别的航班号或机场信息由执行者按语义保留。
- 地铁用轻量连接条与实际地铁站名；有站点数据才显示站名，不能把饭店名称换皮成站名。
- 高铁与飞机没有“查看路线”。市内交通是否显示路线操作取决于真实可画路径。
- 视觉任务负责容器与排版；交通内容去重任务负责交通分支的呈现。两个任务串行修改共有文件。

## 4 标题文字方向

用户要求最终阶段增加模型写标题。本轮同时参考 `humanizer-zh` 的规则：用具体内容写一句自然的话，删掉口号、空泛意义和机械对仗。10–15 字是用户给的目标范围，不能用代码截断句子达到字数。

以下只示范口吻，不代表替已生成行程纠错，也不保证截图中日期的景点开放情况：

| 现状 | 文案示例 |
| --- | --- |
| 北京市＋上海市 5 日 | 去北京看秋色，再到上海走走 |
| 东来顺饭庄（王府井店）· 转场与游览 | 坐高铁到北京，晚上吃顿涮肉 |
| 故宫博物院与景山公园 · 游览与美食 | 逛完故宫，再去景山看看秋色 |
| 颐和园与恭王府 · 游览与美食 | 去颐和园走走，再逛恭王府 |
| 天坛公园 · 转场与游览 | 看过天坛，就出发去上海 |
| 上海博物馆与豫园 · 转场与游览 | 在博物馆和豫园逛完最后一天 |

示例中的顺序只有在真实行程支持时才能用于生产。模型只润色旅行总标题与每日主题，日期、目的地、站点、交通、价格和开放时间仍由正式行程提供。
