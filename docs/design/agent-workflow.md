# JourneyPilot Agent Workflow Design

---

## 0. 这份文档是什么

JourneyPilot Agent 框架的完整设计：它为什么这么建、怎么运行、边界画在哪。既是重构的依据，也是对外讲述这个 Agent 怎么建的材料。

全文按以下顺序展开：

| 章 | 内容 |
|---|---|
| §1 设计前提 | 全部决定的来源：产品、失败模式、资源、部署前提，与由它们导出的五条公理 |
| §2 拓扑与职责边界 | 节点分类、七个模型调用点、四道门、Worker 的职责边界 |
| §3 一次 Run 的完整生命周期 | 从入口到交付，含取消、挂起恢复、运行中修订与终态归因 |
| §4 契约与状态模型 | RequestContract、Generation、状态字段与门间协议 |
| §5 预算模型 | 时间窗口、封存、成本与重试预算、耗尽时的降级语义 |
| §6 上下文与记忆的注入边界 | 模型能读到什么、读不到什么、为什么 |
| §7 工具治理与证据链 | 工具白名单的三层收窄、接地守卫、证据溯源 |
| §8 对照结论与设计决策 | 与 codex、openpi 对照后确定的决策清单 |
| §9 我们刻意不做什么 | 每条附理由，以及什么条件下会重新考虑 |

每节标题标注 `[现状]`（今天的代码）、`[决策]`（已决定、尚未落地）或 `[混合]`。

## 1. 设计前提 `[现状]`

> 这一章是全部决定的来源。后面任何一条机制，都要能回指到这里的某条前提。

- 1.1 产品前提：交付一份可以拿去执行的行程，不是一段对话
- 1.2 失败模式前提：失败不是「模型不够聪明」，是**约束丢失 + 事实编造**，且**不可回退**
- 1.3 资源前提：稀缺资源是**墙钟秒数**，不是上下文窗口
- 1.4 部署前提：单机 / 单进程 / 单用户（继承 ADR-0001、ADR-0004）
- 1.5 人的可用性前提：**只有一个授权时刻**，之后无人可问
- 1.6 由前提导出的五条公理
  - A1 模型只在可校验的位置说话
  - A2 编排在授权之前完全确定
  - A3 时间与钱在授权瞬间封存
  - A4 「找到了」与「可信」是两个判断
  - A5 只有一个出口
- 1.7 前提变更会推翻什么（哪条前提松动会让哪一章作废）

## 2. Agent 拓扑与职责边界 `[混合]`

- 2.1 三类节点：投影 / 模型 / 人在环——为什么这个分类本身是架构信息
- 2.2 七个模型调用点：逐个说明「为什么这里必须是模型」「它被允许说什么」「它说错了谁兜」
- 2.3 四道门：各自回答哪个问题、拥有哪个预算、能往哪退
- 2.4 一个 Worker 的职责边界：能做 / 不能做 / 为什么
- 2.5 `[提案·待验证]` 执行档（ExecutionProfile）：把 Worker 配置从代码抬成合同投影出来的数据
  > 证据到齐前不升级为 `[决策]`。判据见 comparative-study §2。
- 2.6 拓扑不变量：谁不能调用谁、谁不能写谁的字段

## 3. 一次 Run 的完整生命周期 `[现状]`

- 3.1 入口分流与两张图
- 3.2 合同段：一次归一化，四份投影
- 3.3 授权时刻：`plan_gate` 做的三件事——硬校验 / 封存 / 授权
- 3.4 研究环：`dispatcher` 作为唯一扇出与唯一汇合
- 3.5 组合：三相与相间的产物交接
- 3.6 交付：投影 + 原子提交
- 3.7 非正常路径
  - 3.7.1 取消
  - 3.7.2 挂起与恢复（`ask_user` HALT / 进程重启 / checkpoint 合同失配）
  - 3.7.3 运行中修订（`IntentAmendment` 与五级作废阶梯）
  - 3.7.4 窗口越界：窗口如何**改变图的形状**，而不是抛超时
- 3.8 **终态归因（穷举表）**——本章的核心交付物之一
  > 每一行：结束方式 / 触发条件 / 归因载体 / 用户看到什么 / 库里留什么 / 钉住它的测试。
  > 至少覆盖：正常交付、`RunCancelled`、`ask_user` HALT、`DeliveryContractViolation`、
  > `CheckpointContractError`、租约丢失、`ModelWindowClosed` 降级交付、
  > `DeliveryDeadlineExceeded`、预算耗尽降级、Provider 全失败。
  > 对照笔记：codex 在 core 层**没有**单一 typed 终态，是
  > `Result<Option<String>, CodexErr>` + `Option<TurnAbortReason>` + 侧信道 `terminal_error`
  > 三者的联合，到 app-server 边界才收成 4 值 `TurnStatus`。这一处我们不跟他们学。

## 4. 契约与状态模型 `[混合]`

- 4.1 唯一意图真相：`RequestContract` 及其投影树
- 4.2 Generation 与语义哈希：什么算「改了合同」
- 4.3 State 的三类字段：事实 / 产物 / **协议载体**

- 4.6 `[决策]` 路由边不再重新推导，只投影节点已封存的决策
- 4.7 版本化与破坏性变更策略（继承 ADR-0010/0011/0012：不留兼容读路径）

## 5. 预算模型：时间、成本、重试 `[混合]`

- 5.1 三个嵌套窗口，与「窗口改变图形状」的机制
- 5.2 封存语义：为什么是快照而不是读配置
- 5.3 Run 预算的六个维度与「调用前判、判即记」
- 5.4 离散重试计数：每域 1 次 / 全 Run 3 次——它们各自在防什么
- 5.5 预算耗尽的语义：降级 + 公开偏差，不是失败
- 5.6 `[决策]` 执行档的时间片必须是**封存窗口的划分**，不是新的授予
- 5.7 上游并发闸与 Run 预算的关系（两件不同的事，别混）

## 6. 上下文与记忆的注入边界 `[混合]`

- 6.1 深度路径上模型能读到什么（穷举）
- 6.2 唯一记忆注入通道：Constraint Pack——以及曾经的「双装配」教训
- 6.3 会话轴 vs Worker 轴：为什么偏好开销不进压缩阈值
- 6.4 Worker 上下文的构造：每轮重建还是累积
- 6.5 RAG 的注入边界与 `RAGModePolicy`
- 6.6 `[决策]` 定向补研轮的输入从「新目标」抬成「新目标 + 上一轮的 typed 结论」
- 6.7 明确不做：深度路径不做上下文压缩——前提是 Worker 短命

## 9. 我们刻意不做什么 `[现状]`

> 每条：不做什么 / 为什么 / **什么条件下会重新考虑**

- 9.1 不让模型编排图
- 9.2 不给 Worker 记忆
- 9.3 不做无上限协商
- 9.4 不用温度制造多样性
- 9.5 不保留兼容读路径
- 9.6 不在深度路径做上下文压缩
- 9.7 不执行交易（产品边界）
- 9.8 不用模型自评当门
- 9.9 不做多 Agent 自由对话
- 9.10 不为 CI 花 Provider 的钱
