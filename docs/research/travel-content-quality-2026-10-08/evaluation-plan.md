## 初始场景集

下列是自建评测场景规格，不是已经核验可用的出行推荐。执行时为每题提供明确日期、人数、完整请求和版本化事实快照；官方运营数据需按目标日期验证。每题允许多个好答案，不以某一条固定景点序列为唯一正确答案。

| ID | 需求与故障注入 | 验收重点 |
|---|---|---|
| Q01 | 上海—苏州两日慢游，首日15点抵达、次日17点离开 | 可用时间正确；主动留白有说明；行李/返程准备不被遗漏 |
| Q02 | 苏州文化专题，用户明确偏好博物馆/戏曲 | 多家博物馆可以合理；体验理由不同；不得为强制多样性违背主题 |
| Q03 | 京都带老人，步行上限由用户指定 | 看实际步行与台阶信息；未知无障碍条件需披露；不凭总距离判定适合 |
| Q04 | 北京亲子，包含午休与固定预约 | 午休真实留出；预约锚点保留；不能用成年步速计算全部移动 |
| Q05 | 故宫目标日期某区域临时关闭 | 临时公告覆盖常规导览；入口出口/单向路径/最后入场一致 |
| Q06 | 香港离岛，固定末班回程船 | 岛上游玩与往返交通分开；保留赶船余量；天气或停航触发替代 |
| Q07 | 巴黎，候选池混入已长期闭馆场馆 | 过期优质攻略不能覆盖运营事实；有效替代具有相近用户价值 |
| Q08 | 杭州连续降雨，但不要求全室内 | 区分预报与气候参考；根据强度和用户接受度调整，不机械替换成全馆游 |
| Q09 | 成都美食，明确忌口且餐厅跨区分散 | 禁忌零违规；用餐顺路；避免为名店多次折返 |
| Q10 | 三城五日，有已订酒店与跨城交通 | 固定订单优先；转场日不按完整日容量；不得无理由每天换酒店 |
| Q11 | 用户给出总预算与人数，住宿价格缺失 | 口径明确；缺失不按0元；估算有依据；无法确认是否超支就标未知 |
| Q12 | 用户要求高密度打卡，对照轻松版本 | 两种需求产生不同节奏；高密度仍满足开门/交通/用餐约束 |
| Q13 | 步行—地铁A线—步行；再对照A线—B线 | 公交线路换乘分别为0、1；段数、步行接驳与换乘分别计算 |
| Q14 | 把热门餐厅替换成更近的同类备选，再改酒店 | 重查受影响路线/预算/日期约束；未受影响的事实不随意变化 |

## 三层判定

**一、可执行约束逐项判定，不用总分抵消。** 检查明确禁忌、地点身份、日期和时区、开放/最后入场、已订预约、交通衔接、必要住宿及已知预算上限。每项状态为通过、违反、未知、不适用。全通过率只在所有适用关键项有证据且通过时计入；同时报告未知率，防止丢掉难例制造提升。

**二、按用户目标进行体验盲评。** 两名独立评审阅读完整请求和相同事实包，对重点诉求、路线组织、节奏/留白、体验取舍、操作说明分别给1–5分，并写出对应片段和理由。通用锚点：1=明显妨碍目标，3=基本可用但需用户补工作，5=有依据、贴合需求且行动清楚。评审分歧保留并复核；没有两名真实评审时，应标注代理评审，不能宣称人工盲评。专题文化游不以类别数量打分。

**三、同时报告成本与可靠性。** 每日活动/移动/休息分钟、无解释时间段、可达边缺失率、步行量、价格证据覆盖、已知与估算费用、修复次数、总延迟、调用费用、失败/降级率。酒店接驳与进出站缓冲的覆盖范围需要显式记录；不能把缺失时长当0。

当前不设“超过N公里必差”“每天至少N景点”等统一阈值。硬阈值优先来自用户限制和运营规则；软阈值经跨城市、旅行方式和人群样本校准后再决定。

## 因果对照与记录

对每题固定请求、候选事实、来源时间、模型版本、预算及可用工具；保留合同→查询→候选→准入→选择→骨架→路线→修复→最终报告的轨迹和每次淘汰原因。至少重复3次，记录种子（若该阶段支持）及无法控制的随机性；先跑小样本定位，再扩充验证集。

比较四个版本：A现有流程；B仅优化提示词；C在同候选池中增加每日设计与组合选择；D在C基础上增加交通反馈和体验检查。维持相同事实准入标准，分别报告逐题结果与聚合分布，不仅给平均总分。

固定事实回放用于测规划；在线回归单独测检索、新鲜度和服务波动。对自建评测，不混用 TravelPlanner 官方成绩与本产品成绩；若另跑其官方评测，遵守数据集和评测规则。

建议发布条件：评测集禁止型硬约束无违规；已知日期/交通冲突不被包装为可执行；关键未知项可见；相对A体验改善且失败率、延迟和费用处于团队确定的容忍范围。容忍范围需在运行前设定，不能看结果后调整。

研究初版只建立规格。后续修复已进行真实在线生成与编辑验证，见 [实施记录](implementation-results.md)；上述完整矩阵及严格对照实验仍未执行。
