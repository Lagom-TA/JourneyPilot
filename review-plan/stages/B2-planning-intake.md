## 审查项

- [x] **主图结构**：逐个过节点和边，确认每个节点职责单一、入口和出口清楚；三处回环（理解 ↔ 理解门、确认门回退、意图修改路由）不会死循环，也不会丢失状态。
- [x] **语义分流**：自然语言入口和表单入口最终得到同一份旅行理解；模型的分流结果一定能映射到系统支持的某条路径；明确指定的操作不再经过模型判断。
- [x] **旅行理解**：目的地、出发地、日期、人数结构化，其余偏好保留自然语言；缺失的信息如实留空，不用原文冒充字段；用户原话和追问回答不丢失；下游拿到的是同一份整理结果。
- [x] **追问**：多轮追问、追问中取消、追问中刷新或断开、地点无法核实时的重试。
- [x] **研究设想与确认门**：确认、修改后重新整理、取消、生成失败后重试、计划版本已变化时的处理；确认前允许理解、地点核实和设想生成，正式调研及天气调用须在确认后开始。
- [x] **交付前后的输入边界**：首份正式行程交付前不接受运行中追加；交付后按回答、局部调整、重新规划、追问分流。
- [x] **状态字段**：`planning/state.py` 中有没有只写不读的字段，或用两个字段表达同一件事。
- [x] **设计对照**：未找到设计讨论稿，经用户确认跳过，未执行逐条对照。
