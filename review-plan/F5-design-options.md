# F5 我的行程与偏好资料：方向讨论

采用作者选择的 **开放式旅行档案＋资料正文主从分栏**。实现与验证见 [F5 验收记录](F5-acceptance.md)。作者已确认：延续暖纸、深绿、橙色与粗体中文，大胆重做版式；纸品装饰只在必要处出现。页面只放帮助识别内容、作出选择或完成操作的信息。

## 当前依据

- 调研素材：[清单](../output/review/F5/manifest.md)。12 张桌面 / 手机代表画面，覆盖行程列表、偏好、记忆、风格、创建向导局部、资料空状态和手机导航。
- GPT 6.1 Terra 的独立看图判断：[素材审视](../output/review/F5/terra-study-review.md)。只依据截图与清单，不把按钮存在当作行为已经通过验收。
- 采集使用现有审查数据库，拦截非 GET 业务请求；没有新增规划、模型调用、上传、保存或删除。尚未运行完整 F5 场景矩阵。
- 草案中的旅行名称、日期、风格和资料正文是示例内容，用来比较版式，不代表当前库的数据或模型产出。现有列表不能保证每条记录都有可靠的目的地、日期与封面，正式界面不补造这些字段。

## 需要解决的具体问题

1. 行程封面、标题与摘要重复同一名称，生成次数也出现两次；手机首项与展开记录几乎占满一屏。
2. 相同装饰封面不能区分行程，尤其是同名记录；首项生成记录默认展开，干扰快速找回旅行。
3. 偏好页以大容器和宽松纵向间距组织短设置，手机需要较长滚动；页面与分组重复解释“规划会参考偏好”。
4. 风格列表是外层大面板再套卡片，分类、摘要、标签、“尚未使用”和激活入口密度接近，主次不足。
5. 资料空状态占据整块大框，说明与添加入口分离；用途在标题下和空状态各解释一次。

对应布局问题见 F5-01 至 F5-05。保存、删除、历史只读等行为的定向验证见验收记录。

## 方案 A：开放式旅行档案

**用强标题和开放排版建立辨识度。** 桌面左侧是两行大标题，管理页的次导航也落在这一侧；右侧用分隔线、文字和留白组织内容。保留全局三个入口：新旅行、我的行程、偏好与资料。

- **行程**：名称只出现一次；状态、更新时间和当前动作清楚可见。生成记录默认收起，单次记录不制造一块重复目录。没有可靠旅行信息的会话直接显示真实名称，不伪装成完整旅行手册。
- **偏好**：常用出发地、手填偏好、旅行记忆依次排列；各自的保存边界明确。常用标签直接可选，其余分组按内容长度展开，不为每组补一段用途介绍。
- **风格**：两列开放条目或轻量网格，名称、一句有区分度的规划方式、使用入口；筛选区统一标明内置 / 我的，不在每个内置条目重复“尚未使用”。
- **资料**：文件与文本共用列表，点开后阅读或编辑；正文较长时进入宽面板。空状态缩成一个紧凑的内容组，让添加动作与说明相邻。
- **手机**：左栏转为标题和必要的分类导航，列表单列；不把桌面分栏缩小硬塞进去。抽屉中的每个目的地只出现一次。

优势是适合当前以文字、状态和操作为主的内容，少量与大量记录都能成立；也与 F3 的研究台面、F4 的开放日程形成连续气质。代价是标题、行高与展开层级必须有清晰节奏，过度压缩会变成普通表格。

草案：[桌面](../output/review/F5/option-open-D.png)、[手机](../output/review/F5/option-open-M.png)。

## 方案 B：主从分栏

**把列表变成持续选择的目录。** 桌面左侧保留轻量页面入口，中部是紧凑记录，右侧显示当前选择的结果入口、历史或资料正文。

- 行程先在列表定位，再在详情区打开结果或展开生成记录；切换条目不丢失列表位置。
- 风格列表只显示名称和归属，选中后在右侧查看规划方式、使用或编辑。
- 资料列表与正文并排，适合连续阅读多份材料；编辑仍保留明确保存和取消，不自动写入。
- 偏好仍按设置组直接填写，不为统一外观强行增加一个空详情栏。
- 手机采用列表 → 详情 → 返回列表，恢复原位置；空列表不保留空白右栏。

优势是连续查看历史和资料很快，桌面空间利用充分；代价是主从选择状态更多，手机多一步进入，整体更像编辑工具。当前资料为空，尚不能把大量资料管理当作主要使用场景。

草案：[桌面](../output/review/F5/option-master-D.png)、[手机](../output/review/F5/option-master-M.png)。

## 方案 C：封面式收藏

**让每趟旅行像一件可辨认的收藏。** 桌面用两至三列画廊，标题写在封面内，封面之外只保留状态、更新时间和动作，不再重复一遍名称。

- 没有可信图片时用文字封面，不把同一套山线、路线和票据复制到每张卡上。
- 风格也可用文字封面建立选择感，详细规划方式在打开后展示。
- 历史记录跟随当前条目展开，不把同一趟旅行的多次生成拆成多张收藏卡。
- 偏好与资料仍采用开放设置和列表；内容类型不同，不统一包进画廊。
- 手机单列，封面高度受控，保留一屏比较多个记录的可能。

优势是少量旅行时有收藏感，展示画面最鲜明；代价是浏览密度低，长名称和同名记录更难区分，也需要持续维护有意义的视觉素材。草案采用文字封面，未假设项目具备自动生成目的地图片的能力。

草案：[桌面](../output/review/F5/option-gallery-D.png)、[手机](../output/review/F5/option-gallery-M.png)。

## 三种方案共同的行为边界

| 场景 | 必须表达清楚的结果 |
|---|---|
| 打开旅行 | 已有结果进入 F4；正在运行进入进度；等待输入进入对应确认；历史记录明确只读。取消、失败和中断不暗示点击就会自动恢复。 |
| 标题与身份 | 优先使用可靠的旅行身份或已有名称；不把最后一条 Markdown 回答当作旅行副标题，不为了版式补造日期、出发地和天数。需定向核对现有列表字段能支持哪些身份信息。 |
| 使用风格 | “用于新旅行”比“激活”更接近下一步动作；当前选择就近可见。风格失效时清除失效选择并提供重新选择的入口，不静默带着旧名称规划。 |
| 创建风格 | 四步各有明确任务；用户可直接填写，也可在相关步骤使用 AI 辅助。AI 生成失败与最终保存失败分别显示，填写内容不丢失。创建器采用宽弹层，四步导航在手机上可完整排列。 |
| 单条记忆删除 | 删除列表事实与后续画像更新分开说明；操作及相关内容会参与之后的总结，旧画像在下一次总结前仍可能用于规划。说明放在使用详情与相关确认中，不在每行重复。 |
| 全部记忆删除 | 确认中清楚列出事实、自动画像、关联、对话摘要及管理内容的清除范围；手填偏好和常用出发地保留。成功反馈明确对象，不能只显示“已删除”。不承诺后端没有提供的撤销。 |
| 记忆排序与失败 | 采用现有更新时间顺序；默认不增加每行时间字段。读取失败与真正为空分别显示，管理按钮按可用状态启用。 |
| 资料上传 | TXT、Markdown、PDF、Word；当前配置单份上限 10 MB。格式和实际大小限制放在上传入口附近；上传 / 整理中与失败反馈就近出现，不把分段数作为主要成绩。 |
| 资料保存与删除 | 保存后规划参考新正文；失败时保留草稿与重试入口。删除写清具体对象与失败结果；全部清空仍需单独确认，不伪造撤销。 |

来源依据为根目录 `AGENTS.md`、`docs/invariants.md` 的 INV-MEMORY-001/002 与 INV-UI-001，以及当前设置、风格、资料 API 与页面代码。风格删除失败反馈与部分记忆读取失败的空态问题已在 F5 定向回归中关闭，范围见验收记录。

## 选定方向

作者选择 **A 作为整体结构，资料正文采用 B 的阅读与编辑空间**。风格保留四步创建；取消、失败等状态不暗示自动恢复。三种草案沿用同一品牌色与字体，区别在内容结构。

页面说明去重、历史默认收起、失败反馈和草稿保留随本阶段一起实现。

验收范围限定在受影响路径与代表画面；不重复后端全量测试，不为验收创建或清空业务数据。
