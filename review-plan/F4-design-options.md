# F4 交付工作台：方向讨论

采用作者选择的 **地图画幅＋旅程对页**：全程由满幅地图主导，单日展开日程与地图的对页。视觉目标是大胆、有强烈冲击力的个人代表作，信息表达保持克制。本文记录参考调研、结构比较与选定方向；正式实现及代表状态的验证见 [F4 验收记录](F4-acceptance.md)。

## 目标与依据

JourneyPilot 是个人代表作。交付后的画面应让人看懂这一趟旅行，有鲜明的版式，同时方便查看当天安排和地理关系。沿用 F2/F3 的暖纸、深绿、粗体中文和克制表达；纸品不在每个页面重复铺陈。结果通过会话调整，正文只读。

现状素材：[清单](../output/review/F4/manifest.md)；GPT 6.1 Terra 的独立看图意见：[素材观察](../output/review/F4/terra-study-review.md)。使用当前正式应用、现有审查库的 14 日交付，浏览器阻止非 GET 业务请求；没有新增规划、收费服务调用、天气刷新或数据库写入。本轮只采集桌面和手机代表画面，未覆盖完整审查矩阵。

- **已确认的呈现问题**：地图标记附近出现原样 HTML 文本；长行程日期条末端不够明显；阅读版将“重庆市”“十四日”等语义单元拆开。见 F4-01 至 F4-03。
- **待核对的内容问题**：第 6 天首屏仍显示“自由休息”，未见原始交付的未安排事项；需要对照完整工作台、阅读版及 PDF，不能凭首屏断言全页缺失。
- **结构取舍**：现在桌面以大地图和左侧悬浮长栏组织结果，手机展开日程后地图被虚化。它能成立，但并非唯一选择。
- **冗余表达**：总览中“这 14 天，慢慢走”与“每日安排”同时介绍同一目录；阅读封面的介绍句和字段再次重复目的地、日期与天数。候选中把这些信息合并。

## 地图画幅

**把地理关系放到第一眼。** 地图铺开，左侧采用窄而平的日程索引，不使用带大阴影的悬浮卡；底部用一条城市与停留区间组织全程。通过版面和留白建立地图的主导地位。

- 全程先读城市关系；点击城市查看该段日期，再点击某天。14 天不挤成一条跨屏标签。
- 单日放大到地点和实际路线；索引缩为当天时间线。选点后显示一处详情，不同时堆叠多张地点卡。
- 阅读版独立进入，返回时保留地图视野、日期和选中状态；调整与日程共用一处面板。
- 手机以地图和底部日程面板为主，保留地图可读区域；面板改变高度时不虚化整张地图。
- **优势**：地理关系和选点联动最直观，地图展示镜头有张力。
- **代价**：日程仍受面板宽度限制；无地图数据、只有一天或资料很少时，画面需要有自然的退路。

草案：[桌面](../output/review/F4/option-atlas-D.png)、[手机](../output/review/F4/option-atlas-M.png)。

## 旅程对页

**让日程和地图同时清楚。** 旅行身份只出现一次；主体为开放的时间线与地图对页，采用不等宽分栏。地点、餐饮、交通和住宿按顺序连读，时间、名称和体验说明依靠排版区分。

- 城市是第一层，当前城市的日期是第二层；避免所有日期、图层、阅读和调整争抢一条工具栏。
- 单日默认保留时间、名称、一句必要说明；价格、班次、交通步骤和来源就近展开。没有必要的说明就不补齐。
- 桌面选点只改变一处详情；悬浮只高亮，不移动地图。返回全程恢复原来的日期和滚动位置。
- 手机先读日程，地图按需切入；地点详情返回后保留原卡片位置。草案的上下排列只比较信息顺序，最终交互仍需按选择定稿。
- **优势**：日程与地图联动容易理解，交通、住宿等长内容更有空间。
- **代价**：首屏的地图冲击力弱一些；如果两栏同时塞满信息，会退回普通工具界面的密度。

草案：[桌面](../output/review/F4/option-spread-D.png)、[手机](../output/review/F4/option-spread-M.png)。

## 城市章节

**先把整趟旅行做成一页有节奏的目录。** 全程按城市的实际连续停留段组织开放章节，日期与每日主题直接排版；小地图负责解释城市之间的关系。点进某天，再进入日程与地图的对页。

- 多城市、长行程可以直接比较各段内容；相同城市再次到访时按连续停留段展示，不把跨段日程强行合并。
- 单城市不制造多栏或虚构章节；1 天直接进入当天内容，4–7 天采用紧凑目录，14 天按真实段落排布。
- 单日和调整共用与“旅程对页”相同的内容基础，返回恢复目录位置。全程地图保留明确入口，仍可完整查看。
- 手机只展开当前城市段，城市切换固定在目录首部；不用横向滑动寻找 D14。
- **优势**：最容易看清整趟旅行，也最能与现有生成台面形成连续的作品展示；摆脱默认“大地图加长侧栏”的画面。
- **代价**：全程默认地图较小；喜欢先探索地图的人需要多一步。章节是导航，不应增加抒情介绍或装饰性内容。

草案：[桌面](../output/review/F4/option-chapters-D.png)、[手机](../output/review/F4/option-chapters-M.png)。

## 三种方案共用的取舍

| 信息 / 场景 | 默认呈现 | 按需或触发后出现 |
|---|---|---|
| 旅行身份 | 一次正式标题、日期和天数 | 完整出发地、同行与偏好 |
| 每日安排 | 日期、主题、真实安排；选中后为时间线 | 地点完整介绍、路线步骤、班次明细、单项价格与事实来源 |
| 未安排 | 有实际缺口时，在相关天直接标明；全程提供一个可到达入口 | 完整缺口列表；不在每张卡重复通用提醒 |
| 天气 | 有数据时一行必要信息；分清预报与季节参考 | 新鲜度、来源及会影响安排的调整建议 |
| 阅读版 | 标题与必要元信息后尽快进入正文；目录可达 | 完整叙述、每日内容、参考资料；PDF 在阅读与导出路径提供 |
| 旅中查看 | 今天与接下来的既定安排；非当天明确为预览 | 其他日期；不模拟实时执行或导航 |
| 调整 | 一个清楚的会话入口；地图和日期上下文保持 | 待确认方案、多轮追问、队列与运行异常；需要操作时直接可见 |
| 只读历史 | 当前记录的只读身份 | 不出现调整输入；手机不要求展开长面板才能辨认身份 |

未安排和事实来源是旅行内容，不用“界面克制”掩盖；价格继续按项展示，不新增总价。功能较少时不补占位卡、假图片、假统计或说明性标语。

阅读版三案共用：开放正文、清楚目录、短封面；去掉封面中的重复字段、无内容作用的边框与印章。正式模型文案与数据仍由同一份交付驱动，版式草案中的缩写和文字不直接覆盖真实交付。

## 已选方案

作者选择 **地图画幅为主体，配合旅程对页**。交付打开后先看到地图与整趟旅行的空间关系；选择某天后，日程区域展开为有足够阅读宽度的对页，地图持续保留。返回全程恢复原来的城市段、索引位置和地图上下文。城市段只承担紧凑导航，不采用“城市章节”作为独立首屏。

### 视觉力度

- **满幅构图**：真实地图延伸到工作区边缘，占据首屏主体；旅行身份与窄索引采用开放排版，地图空间由实际内容决定。
- **强烈主次**：标题使用有分量的中文粗体，允许自然换行；深绿、暖纸与路线强调色形成清楚对比。底图信息服从路线和地点的阅读，不让行政区文字与控件争抢焦点。
- **非对称布局**：全程以窄索引与大地图形成明确的面积差；进入单日时索引展开为时间线，地图按实际面板宽度避让。布局变化与用户动作对应。
- **路线作为视觉**：通过真实地点、城市停留段、路线和选中状态呈现旅行的形状。只有端点的连接继续使用示意线，不伪装成道路轨迹。
- **克制表达**：旅行标题、日期、天数各有明确位置；默认突出时间、地点和必要安排。不为每个项目补齐介绍句，不叠加口号、统计或装饰卡片。
- **连续过渡**：全程、单日与会话在同一地图空间衔接；阅读版往返保留地图状态。动效强调空间变化和选中关系。
- **手机结构**：地图与底部日程面板共用上下文，展开日程时保持地图清晰；以面板高度分配查看空间。

阅读版采用短封面与开放正文，完整内容、事实来源和 PDF 由同一交付驱动。正式页面已采用上述构图、字重与对比，并补齐地点聚合、日期导航、手机两档面板、缺口及来源入口。F4-01 至 F4-08 已关闭，验证范围见 [阶段记录](stages/F4-delivery-workspace.md)与 [验收记录](F4-acceptance.md)。

草案只演示版式、城市 / 日期选择、缺口定位、阅读往返和会话区域。地图使用公开行政区边界与城市连线，属于城市关系示意，不是街道底图或已验证的路线；文字沿用真实样本并为排版作缩写，部分体验说明为示例。三种草案均不代表新增规划效果、地点坐标联动或 PDF 验收。
