| 编号 | 来源 | 需要决定的事 | 结论 |

| D-01 | B2-06 | 确认前是否允许需求理解、地点核实和研究设想生成使用可能收费的模型或服务？ | 允许；正式调研及天气调用在确认后开始。 |
| D-02 | B3-09 | 计价人数和范围不同的单项价格如何展示？ | 只展示各项价格，暂不汇总。 |

| D-04 | B5-11 | 启用费用上限时遇到未知价格或不完整用量，是停止后续模型调用，还是继续并提示费用上限失效？ | 继续规划；费用面板提示上限可能无法生效，预算报告将费用余额标为未知。 |
| D-05 | F2-01、F2-02 | 首页的视觉方向与一句话规划的偏好入口如何处理？ | 采用沉浸风景为主体，融合原色拼贴的色块、黑体和错位构图；一句话规划不出现独立偏好控件。信息只服务旅行理解和操作，视觉表达大胆。[设计结论](F2-design-options.md)。 |
| D-06 | F2-03 | 条件表单的人数与预算如何填写？ | 人数点击打开选择面板，常用值与自填按可用宽度排列，不使用加减按钮；预算不显示常识说明，无效输入就近标记。 |
| D-07 | F2-06 | 右侧灵感物件采用哪种纸品形态，如何建立可复用素材库？ | 已选「旅行票据与行李签」。采用同系列纸材与独立印刷图的 16 个基础单元，另提供手机横版行李签；首页只组合主票据与辅助签。完成素材后继续收尾 F2。[素材方案](F2-paper-assets.md)。 |
| D-08 | B6 综合验收 | `infra/compose.yml` 让 PostgreSQL 宿主端口读取 `JOURNEYPILOT_DATABASE__PORT`（默认仍为 55433）的改动自 S0 起一直未提交；现有 `journeypilot-postgres` 容器据此以 55434 创建，而已提交版本写死 55433，该端口现被另一个项目的容器占用。是否提交这处改动？ | 提交。默认值仍为 55433，设置 `JOURNEYPILOT_DATABASE__PORT` 可换端口，应用与 Compose 保持一致；中英文 README 与排障文档已同步（提交 ac523de）。 |
| D-09 | F2-08、F2-09 | 右侧旅行提案如何轮换、表达交互及排列？ | 自动缓慢轮换，悬停或填写时暂停并保留进度；保留手动选择，不设暂停按钮。两件纸呈现同一提案，纸面不写“填入”；用悬浮位移与轻微粒子表达可交互。文字按纸面排布，两纸不重叠；入口使用纸组上方的整宽玻璃横条，当前格磨砂铺满后切下一格。左侧按高度居中、拉开标题与输入卡间距，输入框随内容自动增高，不提供拖拽角。 |
| D-10 | F3 方向讨论 | 生成工作台采用旅行编辑页、研究台面还是聚焦画幅？调研记录默认显示到什么程度？ | 采用「研究台面＋最新动态」。点击任务区展开、再次点击收起，以悬浮反馈与小箭头表达交互，不设“过程与来源”等说明性文字和加号；异常与恢复操作直接可见。见 [F3 设计方案](F3-design-options.md)。 |
| D-11 | F4 方向讨论 | 交付首屏以地图画幅、旅程对页还是城市章节为主？ | 采用「地图画幅＋旅程对页」：全程以满幅地图为主体，单日展开日程与地图对页。通过强标题、路线、对比和非对称构图形成强烈视觉冲击，文案与信息表达保持克制。见 [F4 设计方案](F4-design-options.md)。 |
